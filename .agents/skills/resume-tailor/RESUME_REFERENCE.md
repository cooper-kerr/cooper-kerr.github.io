# Resume Reference

Use this reference when resume craft matters beyond source selection.

## ATS And Formatting

- Use exact job-posting keywords when they truthfully match Cooper's experience.
- Spell out acronyms at least once when space allows, then include the acronym.
- Use standard section headers: `Education`, `Experience`, `Projects`, `Skills`.
- Keep formatting simple: no tables, graphics, unusual section names, or dense multi-column layouts unless the user specifically asks for a designed resume.
- Prefer PDF for final submission unless the employer requests DOCX or plain text.

## Bullet Formula

Use this pattern for experience and project bullets:

`[Action verb] + [specific work] + [metric/result] + [method/context]`

Cooper-specific examples:

- `Redesigned a predictive model estimating wedge launch conditions from 7-iron launch data, achieving 87% prediction accuracy and reducing mean absolute error by roughly 40% across launch-condition metrics.`
- `Engineered a Python and GitHub pipeline to extract, clean, and model 30,000+ real-time options records daily, replacing paid delayed data releases with free daily bubble-estimate updates.`
- `Queried and analyzed athlete performance databases in SQL and Python across 120 practices and games, translating load differences into reports for coaches and performance staff.`

## Verb Families

- Analysis: analyzed, modeled, queried, evaluated, identified, synthesized.
- Technical build: built, engineered, redesigned, refactored, automated, integrated.
- Product/stakeholder: delivered, translated, presented, supported, informed, prioritized.
- Research/statistics: tested, validated, audited, compared, measured, estimated.

## Resume Length

- Internship, student, and early-career roles: target one page.
- Use two pages only when the user asks for a master resume, academic CV, or portfolio-style export.
- If space is tight, cut older or less relevant projects before cutting high-signal metrics.

## Honesty Checks

- If the job asks for direct A/B testing, differential privacy, Hive/Hadoop, causal inference, or distributed systems and the repo does not show it, label it as a gap or adjacent evidence.
- If the user supplies a new fact in the chat, it may be used, but mark it as user-provided when it matters.
- If a bullet sounds stronger after removing a metric, keep the metric when it is relevant; Cooper's applications benefit from specificity.
